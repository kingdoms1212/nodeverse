# Gold 재게시 경합 수정 — 2026-11-23

Gold 데이터의 MongoDB 게시가 실패하면 실패 구간을 저장하고, 주기적으로 다시 게시합니다. 기존에는 재게시 중 새로 추가된 구간을 값의 포함 여부로 판별해, 처리 중 같은 구간이 다시 실패하면 새 항목이 기존 항목과 같다는 이유로 삭제될 수 있었습니다. 그 결과 복구 후에도 해당 구간이 재게시되지 않을 수 있었습니다.

재게시 시작 시 가져온 항목의 개수만큼만 현재 목록에서 제거해 동일한 새 실패 항목을 보존하도록 수정했습니다. 기존 JSON 형식은 유지합니다. 이 보호는 동일 프로세스의 잠금과 기존 단일 게시 작업자를 전제로 하며, 여러 프로세스가 같은 파일에 동시에 쓰는 상황을 보장하지 않습니다.

`tools/gold_republish_race_test.py`에서 게시 실패, 재게시 도중 동일 구간의 새 실패 추가, 계속 실패, 이후 성공을 모의했습니다. 새 실패가 남고 성공 후에만 대기 목록에서 사라지는 것을 확인했습니다. 이 검사는 모의 Delta 읽기와 Mongo 쓰기를 사용합니다. 실제 DB 장애 주입과 스트리밍 체크포인트 복구의 종단 시험은 별도입니다. 운영 서비스에는 아직 재배포하지 않았습니다.
