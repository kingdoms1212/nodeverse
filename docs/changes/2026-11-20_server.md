## 2. 게임 계정 recovery_key를 해시로 저장 (SV-2)

| 항목 | 내용 |
|---|---|
| 이전 | `GameAccount.recovery_key`에 이메일·별명을 평문(소문자)으로 저장 |
| 지금 | `recovery_digest(raw)` = `"h1:" + HMAC-SHA256(키, 소문자로 정규화한 값)` 저장 |
| 키 | `settings.RECOVERY_KEY_PEPPER`가 있으면 그것, 없으면 `SECRET_KEY`. **`SECRET_KEY`를 바꾸면 기존 recovery_key가 맞지 않게 되므로**, 운영에서 키를 바꿀 계획이면 먼저 `RECOVERY_KEY_PEPPER`를 고정값으로 설정할 것 |
| 왜 HMAC인가 | 아이디 찾기(`find-id`)가 recovery_key로 계정을 **검색**해야 하므로 매번 결과가 같은(결정적) 해시가 필요. 비밀번호용 `make_password`(솔트 포함)는 검색 불가. 키를 섞어 DB가 유출돼도 이메일을 역산하기 어렵게 함 |
| 기존 데이터 | `telemetry.0010_hash_recovery_keys` 마이그레이션이 평문 값을 해시로 바꿈(되돌릴 수 없음). 마이그레이션 전 행도 동작하도록 조회·비교는 해시와 평문을 모두 받고, 비밀번호 재설정에 성공하면 해시로 바꿔 저장 |
| 응답 형식 | 게임 클라이언트가 받는 JSON은 그대로 |

바뀐 함수 (`telemetry/game_auth_api.py`):

```python
recovery_digest(raw) -> str        # 정규화(strip, lower) 후 "h1:<hex>"; 빈 값은 ""
_recovery_matches(stored, raw)     # 해시면 해시끼리, 옛 평문이면 평문끼리 상수 시간 비교
game_auth_register   : recovery_key=recovery_digest(recovery_key)
game_auth_find_id    : filter(recovery_key__in=[recovery_digest(key), key])
game_auth_reset_password : _recovery_matches(...) 후, 평문이었으면 해시로 갱신
```

테스트: 저장값이 평문이 아닌지, 옛 평문 계정도 찾기·재설정이 되고 해시로 바뀌는지 (`test_legacy_plaintext_recovery_key_still_works_and_is_upgraded`).

## 4. 게임 쪽 변경 중 서버에 영향 있는 것

- 게임이 더 이상 `/api/game/player-login`을 부르지 않습니다(클라이언트에 `GAME_SERVER_API_KEY`를 둘 수 없어서). 로그인 기록은 `/api/game/auth/login`이 남기고, 학습 이벤트의 `player_id`는 로그인한 회원 ID입니다. `player-login`·`records` API는 서버 간 전용으로 그대로 둡니다.
- 게임 이벤트 ID가 UUIDv7로 바뀌었습니다. 형식은 같은 UUID라 서버 코드 변경은 없습니다.
- 파이프라인의 원격 적재가 빨라져(초당 17~24건 → 60~90건) 분석 화면(`/staff/`, `/staff/events/`)이 실시간에 더 가깝게 따라옵니다.

## 지켜야 할 규칙 (AI 에이전트용)

1. 새 마이그레이션이 다른 앱의 테이블(`django_session` 등)을 건드리면 그 앱의 마이그레이션을 `dependencies`에 넣습니다.
2. recovery_key는 항상 `recovery_digest()`로 저장·검색합니다. 평문으로 저장하거나 `==`로 비교하지 않습니다.
3. 게임 클라이언트가 직접 부르는 API(`/api/game/auth/*`, `/api/game/manifest`)와 서버 간 API(`/api/game/records`, `/api/game/player-login`, `GAME_SERVER_API_KEY`)를 섞지 않습니다. 서버 간 키를 클라이언트가 쓰게 만들지 않습니다.
4. 게임 응답 JSON 형식(`success`, `message`, `usernames` 등)은 Godot 클라이언트가 그대로 읽으므로 바꾸지 않습니다.
5. 테스트 실행 시 `GAME_SERVER_API_KEY`를 비워 둡니다(CI와 같은 조건). 로컬 `.env`에 값이 있으면 `test_no_admin_access_for_anonymous_game_client`가 401≠503으로 실패합니다.
