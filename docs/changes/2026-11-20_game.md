# 게임 파트 변경 구현서 (2026-11-20)

> 이 문서는 게임 담당자와 담당자의 AI 코딩 에이전트가 읽고 이후 작업의 기준으로 삼기 위한 것입니다.
> 각 항목은 **무엇을 · 왜 · 어디를 · 어떻게 확인하는지**를 담고 있으며, 아래 "지켜야 할 규칙"은 이후 변경에도 그대로 적용됩니다.

- 저장소: `encore-ai-campus/mlo-02-p3-team1`, 폴더 `game/`
- 기준 엔진: Godot 4.7.2 (다른 버전으로 열면 `.import`·씬 파일이 대량으로 바뀝니다)
- 바뀐 파일: `game/scripts/network_manager.gd`, `game/scripts/tools/live_test_bot_overlay.gd`

## 1. 이벤트 ID를 UUIDv7(시간순)로 생성

| 항목 | 내용 |
|---|---|
| 무엇을 | 학습·업데이트 이벤트의 `event_id`를 `generate_uuid_v7()`로 만든다 (`_create_event`, `_create_update_event`) |
| 왜 | 파이프라인 Silver 테이블이 `event_id` 기준 MERGE로 중복을 막는데, 무작위 v4 ID는 Delta 파일의 최솟값·최댓값 통계를 쓸모없게 만들어 매번 전체 파일을 읽게 한다. v7은 앞 48비트가 밀리초 시각이라 ID가 시간순으로 커지고, 파일별 ID 범위가 좁아져 MERGE가 최근 파일만 읽을 수 있다 |
| 어디를 | `network_manager.gd` `generate_uuid_v7()` (RFC 9562: 48비트 Unix ms + 버전 7 + variant 10 + 난수) |
| 바뀌지 않은 것 | 형식은 같은 UUID 문자열이라 수집기·계약·서버는 그대로. `session_id`, `run_id`, `attempt_id`, 설치 ID는 v4 유지 |
| 확인 | 게임을 실행해 보낸 이벤트 18건이 모두 v7(`xxxxxxxx-xxxx-7xxx-...`)이고 수집기 202 (2026-11-20 로컬 확인) |

## 2. 전송 큐가 막히지 않게: 응답 코드별 처리 변경

`_handle_network_failure(reason, code, body)`

| 응답 | 이전 | 지금 | 이유 |
|---|---|---|---|
| 401 (키 틀림) | 이벤트를 `rejected/`로 옮김 → 키를 고쳐도 다시 안 보냄 | **pending에 남기고 60초 간격으로 재시도** | 이벤트 잘못이 아니라 이 PC의 설정 문제. 키를 고치면 자동으로 전부 전송됨 |
| 422 (형식 오류) | rejected | rejected (같음) | 같은 본문은 다시 보내도 실패 |
| 400·404·413 등 그 밖의 4xx | 맨 앞 이벤트가 영원히 재시도 → **뒤의 모든 이벤트가 막힘** | **rejected로 옮기고 다음 이벤트 진행** | head-of-line 막힘 해소 |
| 408·429·5xx·네트워크 오류 | 1~60초 지수 백오프 재시도 | 같음 | 일시적 장애 |

## 3. 6일 지난 이벤트는 로컬에서 만료

- `_try_flush_queue()`가 보내기 직전에 `_is_expired(ev)`로 `occurred_at`을 확인해 6일(`MAX_EVENT_AGE_SEC`)이 지났으면 `rejected/`로 옮기고 다음으로 넘어간다.
- 이유: 수집기가 6일 넘은 이벤트를 `too_old`로 거절한다(파이프라인 계약 `MAX_EVENT_AGE`, 결정 D20). 오프라인으로 오래 쌓인 큐가 서버에 보내 봐야 거절될 이벤트로 막히지 않게 한다.

## 4. 미등록 미니게임 ID는 보내지 않음

- `resolve_minigame()`이 카탈로그(`learning_catalog.gd`, 24종)에 없는 ID에 대해 **`["", ""]`** 를 돌려준다. 이전에는 `["ST01", "DS"]`로 바꿔서 배열(ST01) 통계를 오염시켰다.
- `_create_event()`는 미니게임이 비어 있으면 경고 로그만 남기고 빈 딕셔너리를 돌려주고, `_dispatch_event()`는 빈 딕셔너리를 무시한다.
- 예외: `test_connection()`(F6 패널 연결 시험)은 현재 과제가 없으면 이전처럼 ST01로 보낸다.
- 영향: 3D 월드 퀴즈처럼 미니게임 ID가 없는 곳에서 나가던 학습 이벤트는 더 이상 전송되지 않는다. 그런 행동도 기록하려면 계약(`pipeline/contract.py`의 `MinigameId`)에 새 ID를 추가하는 것부터 세 파트가 합의해야 한다.

## 5. player-login 호출 비활성화

- `sync_player_login()`은 `ENABLE_PLAYER_LOGIN_SYNC = false`일 때 아무것도 하지 않는다(기본값 false).
- 이유: `/api/game/player-login`은 서버 간 전용 API라 `GAME_SERVER_API_KEY`가 필요한데, 이 키는 클라이언트에 넣으면 안 된다. 기존 코드는 수집기 주소로 수집 키를 보내 항상 실패했다.
- 대신: 로그인 기록은 `/api/game/auth/login`이 남기고, 학습 이벤트의 `player_id`는 이미 로그인한 회원 ID를 쓴다(커밋 88394b1).
- 주소는 혹시 켤 경우를 위해 Django(`get_api_base_url()`)로 고쳐 두었다.

## 6. 테스트 봇(F5) 전체 코스가 멈추던 문제

- 원인: 메인 섬에서 봇이 `world._on_interact()`를 무조건 호출 → 로봇이 컴퓨터 근처면 2D 메뉴로 전환되며 3D 월드가 트리에서 빠짐 → 봇이 빠진 월드를 계속 조작 → `await world._open_computer_game()`이 트리 밖 노드의 트윈을 영원히 기다림.
- 수정 (`live_test_bot_overlay.gd`):
  - `_world_in_tree(world)`, `_near_computer(world)` 도우미 추가
  - 컴퓨터 근처이거나 NPC 대화 중이면 `_on_interact()`를 부르지 않음
  - 월드가 트리에서 빠졌으면 `_return_to_3d_world()`로 돌아온 뒤 진행
  - 월드가 이미 2D로 넘어갔으면 `_open_computer_game()`을 호출하지 않음
- 확인: 수정 후 봇이 ST01 → SQL01 → ALG01까지 자동 플레이하며 이벤트 전송 (스크린샷 `docs/screenshots/game-3-minigame-bot.png`)

## 지켜야 할 규칙 (AI 에이전트용)

1. **이벤트 형식의 기준은 `pipeline/contract.py`** 입니다. 필드·이벤트 종류·`details` 허용 키·미니게임 24종을 바꾸려면 파이프라인·서버와 먼저 합의하고 `contract.py` → `contracts/` → 게임 순으로 고칩니다.
2. `event_id`는 `generate_uuid_v7()`로 만듭니다. 재전송할 때는 **같은 event_id와 같은 본문**을 보냅니다(파이프라인이 중복을 걸러냄).
3. 같은 세션 안의 `sequence`는 1부터 빠짐없이 증가해야 합니다. 번호가 비면 서버 쪽 적재가 그 세션에서 멈춥니다.
4. `occurred_at`은 UTC 밀리초 `YYYY-MM-DDTHH:MM:SS.mmmZ`(`get_iso_timestamp()`).
5. 수집 키(`auth_token`)·서버 간 키를 코드·씬·커밋에 넣지 않습니다. 주소와 키는 `user://network_config.json` 또는 F6 패널로 설정합니다.
6. 4xx를 새로 처리할 때는 "같은 본문을 다시 보내면 성공할 수 있는가"로 재시도/rejected를 나눕니다.

## 남은 과제

- 서버 주소 기본값이 IP로 고정(`DEFAULT_HOST 192.168.0.81`, `DEFAULT_API_HOST 192.168.0.29`). 서버 manifest에서 받아오는 방식 검토(GM-6).
- `hint_step` 미전송으로 서버 화면에 "단계 None" 표시(GM-7).
- 런처 없이 실행하면 실행·종료 이벤트가 없음(GM-8).
